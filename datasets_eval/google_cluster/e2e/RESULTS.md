## Allocator used: REFERENCE ALLOCATOR (faithful stand-in)

The real optimizer (`ASAPQuery-backend/control_plane`, `POST /api/v1/plan`)
emits only the `{sketch type, size}` part of the tuple today (bind rules +
`tco`/`wire` cost); the `{routing, p, ε_cdm}` axes are the **documented
extension** this figure evaluates (`docs/evaluation-plan-figures.md` Fig 12,
status mark "build-out"). Standing up the Rust HTTP server + a live workload was
not required to produce Fig-12 numbers, so we use the **reference allocator**,
which replicates the in-tree rules **line-for-line**:

| axis | reference allocator mirrors | real source |
|---|---|---|
| sketch type | `kind → family` | `bind_ddsketch_quantile` / `bind_hll_cardinality` / `bind_cms_count` / `BindCountSketchOnTopK` / `bind_exact_agg` |
| KLL `k` | `kll_k_for_eps` (200/400/800/2048/8192) | `sketch_algebra/rules/bind_kll_quantile.rs` |
| DDSketch `α` | `α = ε` snapped to a rung | `bind_ddsketch_quantile.rs` |
| HLL precision | `hll_precision_for_eps` (10/12/14/16) | `bind_hll_cardinality.rs` |
| CMS `(w,d)` | `w=⌈e/ε⌉, d=⌈ln(1/δ)⌉` | `bind_cms_count.rs`, `bind_cms_topk.rs` |
| wire bytes | `WireCostTable::default_phase_eps_1` | `optimizer/cost/wire.rs` |
| TCO shape | EC2 \$0.384/h, S3 \$0.023/GB-mo, transfer \$0.09/GB | `optimizer/cost/tco.rs` |

To re-run against the **real** optimizer once it serves the full tuple:
`python3 controller_alloc_eval.py --use-optimizer http://localhost:8080`.

> **NOTE on the topk binding:** the real rule is `BindCountSketchOnTopK` — it
> emits **CountSketch-with-heap**, *not* CMS. The reference allocator therefore
> assigns CountSketch for topk, faithfully reproducing the in-tree choice. The
> large cost-gap on topk (below) is a *real* finding, not a modelling artifact.

## Accuracy-profile library (the oracle's ground truth)

Standard, cited per-family bounds — these are also what the bind rules invert:

| family | bound | reference |
|---|---|---|
| DDSketch | rel-err `= α` | Masson–Rim–Lee, VLDB 2019 |
| KLL | rank-err `≈ 2/k` | Karnin–Lang–Liberty, FOCS 2016 |
| Count-Min | `ε ≈ e/cols`, `δ ≈ e^-rows` | Cormode–Muthukrishnan 2005 |
| HLL | std-err `≈ 1.04/√(2^p)` | Flajolet et al. 2007 |
| CountSketch | `ε ≈ 1/√cols` (L2) | Charikar–Chen–Farach-Colton 2002 |
| sampling | `ε_s = √((1−p)/(p·N))` | coordinated-sampling bound (Fig 3b) |

`ε_cdm` is the CDM ε-gate threshold (Table 1): higher ε_cdm ⇒ fewer sub-window
emits ⇒ cheaper egress but more open-window error. The freshness SLA is an
**upper cap** on ε_cdm; tighter accuracy can force smaller ε_cdm than freshness
alone would.

## (2) Cost-gap — `controller_cost / oracle_cost`

| stat | value |
|---|---|
| min | **1.96×** |
| median | **2.49×** |
| P95 | **65.70×** |
| max | 65.70× |

**"within X%" (= P95): the controller is within ~66× of oracle cost at P95** —
but that tail is *entirely* the two topk queries; the **median is 2.5×**.

Which knob overpays (count of queries): `{size: 2, p: 0, ε_cdm: 9}`.

- **ε_cdm (9/11, ~2× each):** the controller's *static budget-split* spends
  ≤30% of the accuracy budget on ε_cdm and snaps to the coarsest grid rung that
  fits — but the oracle proves a larger ε_cdm (fewer emits) is still feasible.
  The controller therefore over-emits by ~2–2.5×. **This is the cost of *not*
  jointly co-optimising** — exactly the gap Fig 12 is meant to quantify.
- **size (2/11, topk = 65.7×):** CountSketch's wire state (~250 KB ref) dwarfs a
  CMS-heap (~4 KB ref); under a loose `recall ≥ 0.9` SLA the oracle takes the
  far cheaper CMS-heap. The bind rule's hard-coded CountSketch overpays badly on
  topk. **Actionable: route topk to CMS-heap when the recall SLA is loose.**
- **p (0/11):** sampling is ~cost-neutral here — it cuts edge CPU (a small term
  at these ingest rates) but not sketch wire-state size. Consistent with the
  threat-table line "sampling's win is bandwidth/ingest, not CPU."

## (3) Accuracy-met — 11/11 PASS

Predicted `ε_sk + ε_s + ε_cdm ≤ SLA` for **every** controller allocation
(the harness prints the per-query split). The allocator is sound.

**Cross-validation of the profiles against the empirical numbers we already
have** (all PASS):

| check | predicted | measured (Fig 1/3b) | verdict |
|---|---|---|---|
| DDSketch α=0.01 | ≤ 1.0% | p99 rel-err 0.34% | PASS (bound conservative, holds) |
| ε_s(p=0.25, N=44) | **0.261** | 15–18% | PASS — `√(0.75/(0.25·44)) = 0.261`, same order; bound is the upper envelope |
| ε_s(p=0.25, N=165) | 0.135 | 0.6–1.7% | PASS — degenerates toward α as N grows |
| KLL k=200 | 0.010 | in-tree `kll_k_for_eps(0.01)=200` | PASS — rung inverts exactly |
| HLL p∈{10,12,14,16} | 3.25/1.6/0.81/0.41% | in-tree rung table | PASS — `1.04/√(2^p)` reproduces it |

The `ε_s` half is the validated lynchpin: the formula predicts **exactly where
small-N sampling breaks** (N=44 → 0.26), matching the measured 15–18%.
