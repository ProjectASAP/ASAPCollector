# Prometheus client profiling findings

Snapshot date: 2026-04-27

## Setup

- Producer: `deploy/fake-exporter` with `EXPORTER_CLIENT=prometheus`.
- Library: `github.com/prometheus/client_golang v1.23.2`.
- Phases: `update-only`, `scrape-only`, and `combined`.
- Update modes: `cached` and `dynamic`.
- Instruments: `counter,gauge`.
- Matrix: 60 cells from 2 cardinalities, 3 frequencies, 3 scrape intervals, 2 update modes, and 3 phases.
- Per cell: 60 second soak, 30 second CPU profile, heap profile after the CPU profile.

The measured path is:

```text
synthetic app -> Prometheus Go client -> /metrics scrape
```

The collector is not in this path.

## Result Files

- CSV: `prom-client-profiling-20260427-151128.csv`
- Run log: `prom-client-profiling-20260427-151128.log`
- Local profile summaries: `profiles/*.top.txt`
- Local raw pprof profiles: `profiles/*.pb`
- Local per-cell logs and scrape timing: `logs/*`

The local profile and per-cell log directories are intentionally ignored.
The PR keeps the same artifact shape as the SDK-cost PR: findings, summary
CSV, and top-level run log.

## Key Results

- The full run completed all 60 cells.
- At `C=10000`, `F=1000`, `update-only`, cached updates used 3.944 CPU cores. Dynamic label lookup used 31.688 CPU cores.
- At `C=10000`, `F=1000`, `combined`, `S=1s`, cached updates used 4.600 CPU cores with 67 ms p95 scrape latency. Dynamic label lookup used 31.723 CPU cores with 172 ms p95 scrape latency.
- At `C=10000`, `scrape-only`, `S=1s`, both cached and dynamic modes produced about 1.39 MB/s of scrape payload. P95 scrape latency was 55 ms for cached and 58 ms for dynamic.
- The largest RSS observed was 98.120 MiB in the dynamic `combined` cell at `C=10000`, `F=1000`, `S=1s`.

## Profile Notes

- Dynamic high-rate cells are dominated by Prometheus label lookup and synchronization:
  `MetricVec.GetMetricWithLabelValues`, `MetricVec.hashLabelValues`, `metricMap.getMetricWithHashAndLabelValues`, and `sync/atomic.(*Int32).Add`.
- Cached high-rate cells avoid per-event label lookup. Their CPU profile is mostly runtime scheduling/timer work plus direct counter and gauge updates.
- Scrape-only profiles are much smaller. The visible scrape path cost is mostly metric collection, sorting, text exposition, and GC.

## Caveats

- The `docker stats --no-stream` CPU values are point-in-time samples. Use the pprof files as the stronger source for hot functions.
- Some readiness probes logged transient connection resets while high-cardinality dynamic cells were starting. The cells still completed and wrote CSV rows.
- This is producer-side Prometheus client cost only; collector sketch construction and merge costs remain covered by the existing sketchcollector and PR #195 SDK profiling paths.
